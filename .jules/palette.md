
## 2024-05-18 - Non-blocking Dialogs and ctk Dynamic Layout Quirks
**Learning:** In asynchronous applications (like this subtitle generator), showing a blocking dialog (like `tkinter.messagebox.showinfo`) to signal success freezes the UI unexpectedly. Using inline UI states, like replacing a Cancel button with an Open Location button, is vastly superior. Furthermore, when dynamically adding widgets to `customtkinter` layouts using `pack(side="left")`, simply packing the new button makes it appear at the end (far right). To insert it correctly alongside existing buttons, the existing buttons must be sequentially unpacked (`pack_forget()`) and then all buttons repacked in order.
**Action:** Default to non-blocking inline success states rather than `messagebox.showinfo` for long-running processes. When writing dynamically changing layouts in `customtkinter`, always `pack_forget()` existing sibling widgets and re-`pack()` them sequentially to ensure the correct visual left-to-right order.
